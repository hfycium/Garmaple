# Garmaple

**用你自己的佳明历史数据，直接向 AI 问训练问题。**

Garmaple 读取你从 Garmin 官方导出的数据，在你自己的电脑上整理好，再通过 MCP 交给 AI 助手查询。

你**不用**把 Garmin 账号密码交给任何第三方，**不用**注册账号，**不用**联网。

---

## 它能帮你做什么

问 AI 就够了，不用记命令，也不用记工具名。

| 你想问的 | AI 会去做什么 |
|---|---|
| 「最近一个月我跑了多少？」 | 汇总这段时间的训练量、配速、运动类型 |
| 「这次跑步后半程是不是掉速了？」 | 看心率和配速的逐秒变化，判断有没有「跑废了」 |
| 「睡得好日子是不是跑得更快？」 | 把睡眠、压力和第二天的表现放一起做统计比较 |
| 「我的 5K 最好成绩是多少？」 | 查个人最佳纪录，以及设备预测的比赛成绩 |
| 「这双鞋还能跑多少公里？」 | 按关联过的活动估算鞋子的累计里程 |
| 「帮我做一份间歇训练课表」 | 生成课表文件，你拷进手表就能用 |

具体的例子：

- 「最近几周训练量和配速有什么变化？」
- 「睡眠和压力与我第二天的跑步表现有没有统计上的关联？」
- 「这次跑步后半程的心率和配速是否出现明显漂移？」
- 「我的比赛预测和真实个人最佳分别是什么？」
- 「帮我生成一份包含热身、间歇和放松的时间课表。」

Garmaple 会告诉你数据覆盖到哪一天、哪些数据缺失，也会说明哪些结论只是统计关系、不能当因果。

## 开始使用

你要亲手做的只有一件事：**去 Garmin 官网申请数据导出**——要登录你的账号，这步没人能代劳。下载到 zip 之后，其余全部交给 AI agent。

### 你要做的：申请导出，等邮件，下载 zip

打开下面的页面，登录你的 Garmin 账号，找到「导出您的数据」并提交申请。

- 中国区：<https://www.garmin.cn/zh-CN/account/datamanagement/exportdata>
- 国际区：<https://www.garmin.com/account/datamanagement/exportdata>

Garmin 准备好后会**发邮件给你下载链接**，收到后下载那个 `.zip` 压缩包。

> ⏳ 官方说明通常需要约 **48 小时**，最长可能到 30 天。这是 Garmin 官方流程，早点申请。

### 剩下的：一份提示词交给 agent

下载完成后，把下面整段发给你的 AI agent（需要的是能操作你电脑文件、运行命令的助手，普通网页版聊天不行）。尖括号换成实际内容；不知道路径，就照原样写「在我的下载文件夹里」，agent 会自己找。

```text
请帮我在本机安装并配置 Garmaple（https://github.com/hfycium/Garmaple），
把我的 Garmin 官方导出数据接入你，让我之后可以直接向你提问。

我的导出 ZIP 已经下载好了：<粘贴 ZIP 文件的完整路径，或写「在我的下载文件夹里」>

请完成：
1. 安装 Garmaple 并确认 garmaple 命令可用；
2. 建好工作目录和 data 子文件夹，把 ZIP 原样放进去（不要解压、不要改名）；
3. 运行 garmaple index 建立本地索引，再用 garmaple doctor 自检；
4. 配置本客户端的 MCP 连接（GARMAPLE_DATA 指向那个 data 目录，
   隐私级别用默认的 strict），并确认连通、数据覆盖范围正常。

要求：全程在本机处理，不要上传或分享这个 ZIP，不要索要我的 Garmin 账号密码。
如果有步骤必须我亲自操作，请一次只告诉我一个具体步骤。
```

agent 跑完就可以直接问了，比如「我的佳明数据覆盖到哪一天？」「最近一个月跑了多少？」。

**数据更新怎么办？** 重新导出一份 zip，告诉 agent 放进同一个 `data` 文件夹并重新索引。索引是纯派生数据，重建不会丢东西。

**AI 说找不到数据？** 让它跑 `garmaple doctor` 检查三件事：ZIP 是否在 `data/` 里、索引是否建好、MCP 连的是不是同一份索引。

## 它怎么保护你的数据

Garmaple 在**你自己的电脑上**读取导出文件。它不登录 Garmin、不联网、不向任何服务器发送数据。

但有一件事必须说清楚：**接上 AI 之后，工具返回的内容会进入 AI 的对话上下文**，也就可能传给那个 AI 服务背后的模型提供方。这是所有「让 AI 读本地数据」的方案共有的环节，躲不掉，也不该假装躲得掉。

Garmaple 能控制的是**它返回给 AI 的内容**：

| 隐私级别 | 返回什么 |
|---|---|
| `strict`（默认） | 不返回 GPS 坐标和地点字段；活动只显示日期，活动编号会被替换成一个假编号。活动名、装备名这类文字里仍可能带地名 |
| `normal` | 不返回 GPS 坐标；保留精确时间和原始活动编号 |
| `raw` | 返回原始位置与标识信息，只在你确实需要时开 |

不确定就用默认的 `strict`。想改的话，让 agent 帮你改配置就行。

> ⚠️ **本机的文件也要自己保管好。** 隐私级别只管「交给 AI 的内容」，不会清理原始压缩包和本机生成的索引文件。它们里面仍然有 GPS 坐标、地点和活动标识——别发给别人，也别上传到公开仓库。

## 用之前值得知道的

- **这是历史数据工具。** 导出完成之后新跑的活动不会自动出现，要重新导出。
- **设备记了什么，才能分析什么。** 比如功率曲线需要手表真的记了功率，没记的时候工具会直说「这次没有」，不会拿零来充数。
- **有些数据官方导出包里根本没有。** 比如睡眠评分——Garmin 不导出这个数值，所以 Garmaple 也不提供。
- **相关不等于因果。** 「睡得好那天跑得快」不能证明是睡眠让你跑得快，也可能只是那天排了强度课。
- **课表功能还没有实机验证。** 课表文件支持按时间分段（热身 / 间歇 / 放松），生成后需要你手动拷进手表。作者用的是一台比较早的 Garmin 245，没法验证所有设备的表现——欢迎用别的设备的同学反馈兼容性。

## 它到底能读到什么程度

这一节给想了解细节的人。Garmaple 有 **18 个 MCP 工具**，分三类：

**看数据** —— `get_data_overview`（覆盖范围）、`list_activities`（列活动）、`get_activity`（单次详情）、`get_period_summary`（区间汇总）、`get_daily_summary`（每日步数/压力/电量）、`get_sleep`（睡眠时长与分期）

**做分析** —— `get_activity_streams`（逐秒曲线）、`get_pace_hr_drift`（配速心率漂移）、`get_hr_zones`（心率区间分布）、`get_training_status`（训练状态）、`get_training_load`（CTL/ATL/TSB）、`get_recovery_correlation`（恢复与表现的相关性）、`get_race_predictions`（比赛预测）、`get_vo2max_trend`（最大摄氧量）、`get_personal_records`（个人最佳）、`get_gear_mileage`（装备里程）、`get_power_curve`（功率持续曲线）

**写出去** —— `export_workout_fit`（生成课表 FIT 文件）

数据来源是 Garmin 官方导出包里的结构化 JSON 和原始 `.fit` 文件：

```
<导出包>.zip
├── DI_CONNECT/DI-Connect-Fitness/       # 活动摘要、个人最佳、训练课表、装备
├── DI_CONNECT/DI-Connect-Wellness/      # 睡眠分期、生物指标
├── DI_CONNECT/DI-Connect-Metrics/       # 训练历史、VO2max、赛事预测
├── DI_CONNECT/DI-Connect-Aggregator/    # 每日汇总、饮水
└── DI_CONNECT/DI-Connect-Uploaded-Files/ # 全部原始 .fit 文件
```

几处容易踩坑的地方：

- **睡眠按醒来那天归档。** 问「昨晚睡得怎么样」要查今天那条，查昨天会拿到前一晚的。
- **心率区间只有时长，没有区间边界。** 导出包里只有每档花了多少时间，没有「Z3 是多少 bpm」这种上下限定义。
- **活动与 `.fit` 文件之间没有共同编号。** 只能靠开始时间对齐，所以曲线不是每次活动都有。
- **步频是单脚计数。** 跑步时每分钟步数大约是它的 2 倍。

### 自己动手安装与配置（可选）

不想经过 agent 的话：

```bash
pip install git+https://github.com/hfycium/Garmaple.git
garmaple index     # 解析导出包，建立本地索引
garmaple doctor    # 自检：数据包、分片数量、索引状态、隐私级别
garmaple serve     # 启动 MCP 服务
```

> ⚠️ Garmaple **还没有上架 PyPI**，`pip install garmaple` 装不到，认准上面那条。需要 Python 3.10+ 和 [Git](https://git-scm.com/)。

导出包直接整个 `.zip` 放进 `data/` 就行，不用解压；想放别处用环境变量指：

- `GARMAPLE_DATA` —— 数据目录，默认是运行命令时所在目录下的 `data/`；
- `GARMAPLE_CACHE` —— 索引存放目录，默认 `cache/`；
- `GARMAPLE_PRIVACY` —— 隐私级别，默认 `strict`。

MCP 客户端配置：

```json
{
  "mcpServers": {
    "garmaple": {
      "command": "garmaple",
      "args": ["serve"],
      "env": {
        "GARMAPLE_DATA": "<Garmaple 文件夹的完整路径>/data",
        "GARMAPLE_PRIVACY": "strict"
      }
    }
  }
}
```

写完配置后，多数客户端需要在连接器或 MCP 管理界面手动启用、确认信任一次。`--data` 等参数也可以不走环境变量，直接 `garmaple --data <路径> index`（顶层参数，须写在子命令前面）。

> 升级到新版本后需要重新跑一次 `garmaple index`。索引是纯派生数据，版本号对不上时会被整库丢弃——包括「列没变、但列里存的东西变了」的情况（例如心率区间的单位从毫秒改成秒）。工具此时会返回「请重新运行 index」的提示，不会拿旧数据凑合。

### 和其他方案的区别

| | 需要登录的在线工具 | Garmaple |
|---|---|---|
| 数据来源 | Garmin 服务器 | 你自己导出的归档 |
| 账号密码 | 要交出去 | **完全不需要** |
| 中国区 | 取决于各项目适配情况 | **导出功能本身不分区域** |
| 接口改版 | 得跟着 Garmin 改 | **不依赖接口** |
| 实时性 | 实时 | 要重新导出才更新（唯一代价） |

在线方案和离线方案解决的不是同一个问题。如果你有国际区账号、需要实时数据、或者要写回手表，那些项目更合适，它们在这条路上已经走了很远。

Garmaple 面向的是另一种情况：中国区账号、不想交出密码、只想做历史分析。
